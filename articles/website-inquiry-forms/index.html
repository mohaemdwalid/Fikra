What should a website enquiry form ask?

By FIKRA · Updated 16 October 2026 · 2 min read

Ask only for what helps you answer the enquiry. The right fields depend on whether the visitor needs support, a price or an appointment.

In this guide
  1. Start from the reply you need to give
  2. Match fields to follow-up
  3. Make errors recoverable
  4. Test the receiving process
  5. Ask only what changes the next step

Start from the reply you need to give

If you cannot estimate a project without knowing its type, ask for that. If a budget is uncertain, allow the visitor to say so rather than invent a number. Explain unusual questions and avoid sensitive documents in an ordinary public form. Test errors on a phone: useful information should not disappear after a failed submission. Also confirm who can read stored messages and how follow-up is assigned.

Match fields to follow-up

A quote request may need project type and contact details; a support request may need an order reference. Avoid collecting sensitive documents or unrelated personal information in an open form. Explain why unusual information is needed.

Make errors recoverable

Use visible labels and clear validation. Preserve entered information when a connection fails and avoid announcing success before the server accepts the submission. W3C accessibility guidance supports usable interaction; include keyboard and assistive-technology checks.

Test the receiving process

Confirm where submissions are stored or delivered, who can access them and how follow-up is assigned. Test duplicate taps and failure states. Decide retention and privacy handling for the actual data rather than relying on a template notice.

Ask only what changes the next step

For each field, identify who uses the answer and why. Move information that can wait into the later conversation. Make required fields and errors clear, then test the confirmation and delivery. A shorter form is useful when it still gives the team enough context to respond well.
