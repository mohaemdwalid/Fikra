How do you choose a CMS for a business website?

By FIKRA · Updated 16 October 2026 · 2 min read

Choose a system your editors can use for the content you publish. A flexible dashboard is not useful if every small update needs a developer.

In this guide
  1. Give the editor a real task
  2. Map the content
  3. Check the publishing process
  4. Evaluate ongoing operation
  5. Let the future editor try it

Give the editor a real task

Ask the future editor to add a service, update a project and preview the Arabic version. Can they find the right fields and understand what will change? Check drafts and permissions if several people contribute. Compare the cost of adding a new content type later, not just editing existing text. This reveals the fit better than watching an expert click through a polished demonstration you could not repeat yourself.

Map the content

Identify repeatable items such as services, projects, locations or articles. Decide which fields editors must fill and which pages need custom structure. This makes platform demonstrations more meaningful than comparing empty dashboards.

Check the publishing process

Ask how drafts, approvals, previews and revisions work. WordPress documents publishing and user-management features; other systems arrange these differently. Confirm the capabilities in the actual plan and configuration you would buy.

Evaluate ongoing operation

Review updates, backups, training and the cost of adding a new content type. Give the editor a realistic task and observe the result. Choose the system that supports the expected work, not just the developer’s favourite tool.

Let the future editor try it

Ask the staff member responsible for updates to change a service paragraph, replace an image and publish a draft in a demonstration. Note which actions require a developer. A system that suits the supplier but makes routine edits difficult will create avoidable delays after handover.
